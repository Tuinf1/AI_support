# Прототип агента

## Минимальная демонстрация

1. Принять обезличенные тестовые обращения в JSON/CSV с `ticket_id`, продуктом, временем, статусом, каналом и текстом.
2. Привести текст к единому виду; для аудио и изображений предусмотреть интерфейсы адаптеров к внутренним Qwen-ASR и Qwen-VL.
3. Получить структурированную классификацию по схеме основного решения. До подключения внутренней Qwen 3.8 использовать тестовый адаптер с заранее заданными ответами, чтобы проверить остальную логику без внешних API.
4. Найти ограниченный список кандидатов по продукту, времени и лексике; отдельно предложить связь той же заявки и общую тему разных пользователей.
5. Создать проект карточки сигнала с исходными `ticket_id`, частотой и датами. Публикация происходит только после подтверждения человеком.
6. Вывести журнал решений и простые метрики: точность связок/сигналов на размеченной выборке, задержка, доля нераспознанных обращений.

## Границы первой версии

- Только обезличенные примеры, без реальных записей звонков и персональных данных в Git.
- Без внешних LLM/API, в соответствии с условием кейса.
- Без автоматических изменений исходных тикетов и автоматической отправки сообщений пользователям.
- Данные, логи и результаты запусков хранятся локально и исключены из репозитория.

Следующий шаг — согласовать с командой формат тестовой выборки и язык реализации, затем добавить код и небольшие проверочные сценарии.
